v0.9.3: PURE REST signup (zero clicks) + refcounted debugger sessions

THE BREAKTHROUGH (verified live through the user's browser):
- Full Notion auth flow replayed as REST calls only — no form.fill, no
  clicks, no captcha encounter: getLoginOptions → sendTemporaryPassword →
  code read from the v3-mail worker → loginWithEmail → session cookies
  captured (token_v2 + userId). Recipe + gotchas: docs/NOTION-REST-AUTH.md.
- Key discoveries: Notion-Client-Version header is MANDATORY (400 "Login
  is not allowed" without it); the code email's text_body IS the code;
  chained mail is stored under the APEX address form (admin@priv.email);
  background-tab fetches get throttled (macro focuses the mail tab).
- notion/signup-rest.json: the flow as a 17-step macro (reads the live
  Notion-Client-Version from the signup page — survives Notion deploys).
  Dry-run harness mocks all endpoints incl. request-shape assertions
  (loginOptionsToken/deviceId must flow through; state/password must
  match) — 9/9 macros, 122/122 steps PASS, lint clean.

FIX: reference-counted debugger sessions (debuggerHolders):
- xhr.intercept and form.eval each attach/detach chrome.debugger; the
  first detach killed every other feature's session (latent v0.8.4 bug —
  a daemon-driven interceptor died the moment a subsequent form.eval ran,
  which is why the intercept attempts silently captured nothing).
  Attach/detach is now per-tab refcounted ('macro' holder for runs,
  'xhr:<id>' per interceptor, 'adhoc' for one-shot evals).
  NOTE: requires an extension reload to take effect.

Email reading status: v3-mail worker (full bodies) is the primary path;
named priv.email aliases dual-deliver into it. The REST macro reads it
via the admin-cookie session in a focused tab today; a Bearer
QUERY_API_TOKEN config would remove the tab dependency (token lives in
the mail-kit deploy secrets).
