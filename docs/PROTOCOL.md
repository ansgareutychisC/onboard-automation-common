# PROTOCOL.md — Bridge Wire Protocol v1.0

The bridge wire protocol connects the **unified browser extension** to a **bridge server** (either the `worker-template/` Cloudflare Worker or the `python-template/scripts/run_bridge.py` aiohttp daemon). The bridge server is itself driven by an **orchestrator** (a Python script or Worker route handler) that sends commands and awaits results.

```
┌────────────────┐     commands      ┌──────────────┐     commands      ┌──────────────┐
│  Orchestrator  │ ─────────────────>│   Bridge     │ ─────────────────>│  Extension   │
│  (Python/TS)   │                   │   Server     │                   │  (Chrome MV3)│
│                │<─────────────────│  (Worker/DO  │<─────────────────│              │
└────────────────┘     results       │  /Daemon)    │     results       └──────────────┘
                                       └──────────────┘
```

## Design Principles

1. **The extension is dumb.** It contains zero service-specific logic. Every decision is made by the orchestrator. The extension only executes commands and reports results.

2. **The protocol is symmetric across transports.** A command sent via WebSocket can have its result returned via HTTP POST, and vice versa. The bridge server correlates by command ID, not by connection.

3. **The protocol is versioned.** Every command carries `protocolVersion`. The extension advertises its version in the `connect` message. The server MUST refuse mismatched major versions.

4. **Every command has a `traceId`.** Generated by the orchestrator (or the bridge if the orchestrator omits it), the `traceId` flows through to log entries, results, and async events — enabling end-to-end tracing across the extension, bridge, and orchestrator.

5. **Capability advertisement.** The extension announces which command types it supports in the `connect` message. Orchestrators can probe `/api/extensions` to check capabilities before sending commands that require optional permissions (e.g. `debugger` for CDP-based commands).

## Message Types

| Direction | Type | Purpose |
|-----------|------|---------|
| Ext → Srv | `auth` | Sent immediately on WS open. `{type:"auth", token:"..."}` |
| Srv → Ext | `auth-ok` | Server confirms auth. `{type:"auth-ok"}` |
| Ext → Srv | `connect` | Sent after `auth-ok`. Announces identity + capabilities + context. |
| Srv → Ext | `ping` | Server keepalive (every 30s) |
| Ext → Srv | `pong` | Reply to `ping`, OR unsolicited keepalive (every 25s from extension) |
| Srv → Ext | **command** | One of the command types listed below |
| Ext → Srv | `result` | Synchronous result envelope for a command |
| Ext → Srv | `event` | Async event from an activatable debug stream |
| Ext → Srv | `log` | Structured log entry (best-effort) |
| Ext → Srv | `status` | Periodic status broadcast (popup consumes via `chrome.runtime`) |

## Command Envelope

Every command from server to extension:

```jsonc
{
  "type": "fetch",           // one of CMD.* (see below)
  "id": "cmd_abc123def456",  // server-generated, echoed in result
  "protocolVersion": "1.0",  // optional, defaults to "1.0"
  "traceId": "trace-xyz",    // optional, flows to logs/results/events
  "timeoutMs": 30000,        // optional, per-command timeout
  // ...type-specific payload fields...
}
```

## Result Envelope

Every result from extension to server:

```jsonc
{
  "type": "result",
  "id": "cmd_abc123def456",  // matches the command's id
  "ok": true,                 // false on failure
  "traceId": "trace-xyz",    // echoed from command
  "durationMs": 1234,        // extension-side execution time
  // ...type-specific result fields...
  "error": "..."             // present only when ok=false
}
```

## Command Catalog

### Heartbeat

| Type | Payload | Result |
|------|---------|--------|
| `ping` | (none) | (handled inline — extension sends `pong`) |

### Fetch Family

| Type | Payload | Result |
|------|---------|--------|
| `fetch` | `url, method, headers, body, credentials, timeoutMs` | `status, statusText, body, headers, finalUrl, contentEncoding, bodyLen` |
| `page.fetch` | `tabId, url, method, headers, body, credentials, timeoutMs` | same as `fetch` |

`fetch` runs in the service-worker context. Handles zstd via `DecompressionStream("zstd")` (Chrome 143+), but this is **unreliable in Chrome 151+**. Use `page.fetch` for zstd-bearing endpoints — it runs in the tab's main world where Chrome's network stack handles zstd natively.

### Tab Family

| Type | Payload | Result |
|------|---------|--------|
| `tabs.open` | `url, active` | `tabId, url, title` |
| `tabs.close` | `tabId` | `closed: true` |
| `tabs.list` | (none) | `tabs: [{id, url, title, active, windowId}]` |
| `tabs.focus` | `tabId` | `focused: true` |

### Form Family

| Type | Payload | Result |
|------|---------|--------|
| `form.fill` | `tabId, selector, value` | `value, tagName` |
| `form.click` | `tabId, selector` | `tagName` |
| `form.wait` | `tabId, selector, timeoutMs` | `found, tagName, visible` |
| `form.eval` | `tabId, function, args` | `result` (any JSON) |

`form.fill` uses the React-safe native input value setter pattern — React-controlled inputs accept the value via the prototype's setter + dispatched `input`/`change` events.

`form.eval` uses `chrome.debugger` + CDP `Runtime.evaluate` to bypass both MV3 CSP (which forbids `unsafe-eval`) and the page's own CSP. The `function` field is a string body that gets wrapped as `(function(args){ <body> })(<args>)`.

### Network Capture (one-shot)

| Type | Payload | Result |
|------|---------|--------|
| `xhr.intercept` | `tabId, urlPattern (regex string), method?, timeoutMs` | `xhr: {method, url, requestHeaders, requestBody, responseStatus, responseHeaders, responseBody}` |

Captures the FIRST request matching `urlPattern` (a regex string passed to `new RegExp(...)`). For continuous capture, use `debug.network.start` / `debug.network.stop`.

### Cookies

| Type | Payload | Result |
|------|---------|--------|
| `cookies.get` | `url, name` | `cookie` |
| `cookies.getAll` | `url` | `cookies: [...]` |
| `cookies.set` | `url, cookies: [{name, value, domain?, path?, secure?, httpOnly?, sameSite?, expirationDate?}]` | `results: [{name, ok}], defaultDomain` |

**No default cookie domain.** The caller MUST specify `domain` per-cookie, OR the extension derives it from the URL hostname (`.example.com` form for subdomain coverage). This fixes the legacy bug where `.notion.com` / `.supabase.com` was hardcoded.

### Visual Capture

| Type | Payload | Result |
|------|---------|--------|
| `screenshot` | `tabId, format?, quality?` | `dataUrl, format, tabId, capturedAt` |

**TabId-aware.** Fixes the legacy bug where `chrome.tabs.captureVisibleTab(null, ...)` captured whatever tab was active in the current window, ignoring the requested `tabId`.

### Captcha (multi-provider)

| Type | Payload | Result |
|------|---------|--------|
| `captcha.getToken` | `tabId, provider?` | `token, source, provider, captchaPresent, providerDefined` |

`provider` is one of `hcaptcha`, `recaptcha`, `turnstile`, `cloudflare`. If omitted, auto-detects by probing each provider's window global.

On failure, returns `ok=false` with diagnostic flags: `captchaPresent` (per-provider) and `providerDefined` (per-provider) — so the orchestrator can distinguish "no captcha shown" from "captcha shown but not solved".

### Sandbox

| Type | Payload | Result |
|------|---------|--------|
| `sandbox.open` | (none) | `tabId, opened` |
| `sandbox.fetch` | `url, method, headers, body, credentials, timeoutMs` | same as `fetch` |

`sandbox.open` opens `sandbox.html` as a background tab. The sandbox page connects to the same bridge server with `context:"page"`. The bridge server routes `sandbox.fetch` commands ONLY to connections with `context:"page"` — NOT to the background SW.

### Activatable Debugging

Each debug command is either a **toggle** (start/stop pair returning a `sessionId`) or a **one-shot**. Start commands return immediately with `{ sessionId, startedAt }`. While the session is active, the extension streams events back as `MSG.EVENT` messages. Stop commands return the full captured buffer as their result.

| Type | Payload | Result |
|------|---------|--------|
| `debug.har.start` | `tabId` | `sessionId, startedAt` |
| `debug.har.stop` | `sessionId` | `har: {log: {version:"1.2", creator, entries[]}}, entryCount, durationMs` |
| `debug.console.start` | `tabId` | `sessionId, startedAt` |
| `debug.console.stop` | `sessionId` | `entries: [{ts, type, args, stackTrace}], count, durationMs` |
| `debug.network.start` | `tabId, urlPattern?` | `sessionId, startedAt, urlFilter` |
| `debug.network.stop` | `sessionId` | `entries: [{requestId, request, response, responseBody}], count, durationMs` |
| `debug.trace.start` | `tabId, categories?` | `sessionId, startedAt, categories` |
| `debug.trace.stop` | `sessionId` | `events: [...CDP trace events], count, durationMs` |
| `debug.dom.snapshot` | `tabId, includeShadow?, maxDepth?` | `html, doctype, capturedAt` |
| `debug.storage.dump` | `tabId, includeCookies?` | `localStorage, sessionStorage, cookies?, capturedAt` |
| `debug.screenshot.fullpage` | `tabId, format?, quality?` | `dataUrl, format, dimensions, capturedAt` |

See [DEBUGGING.md](./DEBUGGING.md) for usage patterns and when to use each.

## Async Event Envelope

```jsonc
{
  "type": "event",
  "event": "console.log",     // event name
  "tabId": 123,
  "sessionId": "console_...",  // matches the start command's sessionId
  "traceId": "trace-xyz",     // optional, from the start command's context
  "ts": 1699999999999,
  "data": { ... }             // event-specific payload
}
```

## Structured Log Envelope

```jsonc
{
  "type": "log",
  "ts": 1699999999999,
  "level": "info",            // debug | info | warn | error
  "message": "fetch-start",   // short event name
  "data": { "id": "...", "url": "..." },  // structured payload
  "agentId": "ext-abc123",
  "commandId": "cmd_...",     // present when log relates to a command
  "tabId": 123,               // present when log relates to a tab
  "durationMs": 1234,         // present for "done" logs
  "traceId": "trace-xyz"      // present when context is available
}
```

## Connection Lifecycle

1. **WS open** → extension sends `auth` then `connect`.
2. **Server validates auth** → sends `auth-ok` (or closes with code 1008).
3. **Server registers connection** in its connections map, keyed by `connId`. The `context` field ("worker" or "page") determines command routing.
4. **Keepalive**: extension sends `pong` every 25s (MV3 SW dies after 30s idle). Server sends `ping` every 30s.
5. **Watchdog**: extension uses `chrome.alarms` to force-close the WS if no server message arrives in 90s. The server's sweeper force-closes connections silent for 90s.
6. **Browser-wake healing**: `chrome.idle.onStateChanged` resets backoff and reconnects on wake.
7. **WS close (abnormal)**: extension starts HTTP SOS polling (`GET /api/poll?agentId=...&wait=25`) immediately, then schedules WS reconnect with exponential backoff (1s, 2s, 4s, 8s, 16s, 32s, 60s cap).
8. **HTTP SOS results**: extension POSTs results to `/api/result` with 3 retries + 1s/2s/4s backoff. Server correlates by command ID — resolves any pending WS future for the same ID.

## HTTP Routes (Bridge Server)

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/health` | Liveness probe |
| GET | `/api/token` | Returns `BRIDGE_TOKEN` (for extension bootstrap) |
| GET | `/api/extensions` | List connected extensions + queue sizes |
| POST | `/api/command` | Send a command, await result. Body: `{cmd, timeout}` |
| POST | `/api/send-http` | Enqueue a command for HTTP-polling extension. Body: `{cmd}`. Returns `{id}` |
| GET | `/api/result/:id` | Poll for a result by command ID (404 until ready) |
| GET | `/api/poll?agentId=&wait=` | Extension long-poll for queued commands |
| POST | `/api/result` | Extension POSTs a result (cross-channel resolves WS future) |
| WS | `/ws` or `/` | Extension WebSocket upgrade |

## Authentication

- **HTTP API** (`/api/*`): `Authorization: Bearer <BRIDGE_TOKEN>` checked in middleware. Set `BRIDGE_NO_AUTH=1` to disable (dev only).
- **Extension WS**: extension sends `{type:"auth", token:"..."}` immediately on open. Server compares against `BRIDGE_TOKEN`. Mismatch → close with code 1008.
- **Dashboard WS** (future): no auth by default — protect via Cloudflare Access or add a token query param.

## Versioning

`PROTOCOL_VERSION = "1.0"`. Bump on any breaking change to:
- Command envelope shape (adding required fields)
- Result envelope shape (changing existing field semantics)
- Auth flow
- Message type enumeration

Adding a new command type is **not** a breaking change (capability advertisement handles forward compatibility). Removing or renaming a command type **is** a breaking change.
