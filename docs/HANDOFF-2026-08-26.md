## 4. KEY GOTCHAS learned this session (beyond SKILL.md §8.8)

1. **`notion_tail` CLI helpers `sys.exit()`** — SystemExit (BaseException) KILLED the runner thread silently, jobs stuck 'running' forever. Guarded at 3 levels now (loop BaseException catch, driver `_safe`, chat SystemExit→RuntimeError). Regression test exists. NEVER call those helpers unguarded.
2. **The bash tool's exit-code pipe trap:** `cmd | tail -2; echo $?` reports TAIL's code, not cmd's. The original test suite "passed" this way while actually DEADLOCKING. Always check pytest's own summary line, or use `timeout N cmd` and check $?. Round-1 test review caught the deadlock.
3. **Container recycles kill double-forked daemons** (happened mid-session): DB survives on disk; `recover_stale_jobs()` fails interrupted jobs BY DESIGN — re-enqueue, don't "fix". The flock guard (`data/api.lock`) prevents a second instance from corrupting the live one.
4. **Web fetches MUST go through the Caddy :81 gateway** with `?XTransformPort=3001` — `localhost:3001` from the browser 404s/gets blocked; `localhost:3000` direct also bypasses the gateway entirely.
5. **Legacy dev-daemon vs dashboard port conflict:** bridge.py defaulted to :3000, which the Next.js dashboard now owns — run it on :3002 if you need the extension WS bridge.
6. **Zenrows Browser Session plan limits:** ONE concurrent session; connect-storms → ~4min cooldown; default TTL 180s (enough: whole signup runs 20-60s); `session_ttl`/`session_id` params are plan-gated (REQS004/empty reply).
7. **Polling UI vs status flips:** a cancelled job's status flips BEFORE the runner thread stops working — wait for item quiescence (no running/pending job_items) before asserting outcomes (bit me in the cancel test).
